Anisotropic gyroid lattices

Where
Duke University, Mechanical Engineering & Materials Science
When
Summer 2025
Role
Undergraduate research assistant, self-guided study
Tools
nTop, SLA printing (Formlabs Form 4), MATLAB, Excel, Ansys Mechanical
1 / 6

I planned and carried out a self-guided study on the mechanical behavior of anisotropic gyroid unit cells under tensile and compressive loading. I performed an extensive literature review on TPMS lattices, porous biomaterial mechanics, and bone-implant interface behavior in order to develop background knowledge on the area. For the study, I produced and tested 128 SLA-printed samples across two load types, two stretch directions, four stretch ratios, and two base unit cell sizes. Then, I processed the data in MATLAB and Excel. Stretching unit cells parallel to the loading direction increased Young's modulus while holding ultimate tensile strength steady, whereas perpendicular stretch reduced Young's modulus and ultimate tensile strength.

3H6MGD analog keypad

When

Role

Tools
KiCad, SolidWorks, 3D printing, soldering, libhmk firmware

This project is a custom analog macropad for Geometry Dash, built around magnetic Hall-effect switches. It has three analog jump keys alongside six mechanical keys and a rotary encoder for volume control. Because Hall-effect switches measure how far a key has traveled, the actuation point is adjustable, so you can choose exactly how far down counts as a press.

I designed the PCB in KiCad around an AT32F405 microcontroller utilizing its high-speed USB for 8kHz USB polling to minimize input delay for the linear Hall sensors under each analog switch. I also designed the case, assembled the board, and modified open-source libhmk firmware to add support for the mechanical switches and rotary encoder.

Our team of four members designed and fabricated a robot for a Super Mario Galaxy themed competition. I was responsible for the Stabilize Galaxy Reactor subsystem, which deposits the Lumas into the Galaxy Reactor. For my system the Lumas were held in boxes to ensure proper orientation and prevent jamming, a holder fed them to the correct position, and they were deposited by a pneumatic piston.

The piston was controlled by detectRotation, a helper function that used an IR sensor to detect two passing receptacle walls and record the time between them. The main code then divided that time by two to find when the center of a receptacle was in front of the robot.

#include <myDuino.h>
#include "detectRotation.h"

extern myDuino robot;

// -------------------- SETTINGS (TO TUNE) --------------------
extern int sidePassingThreshold;
unsigned long sampleInterval = 50;
unsigned long printInterval = 200;
unsigned long minWallGap = 1000;

// -------------------- RESTING VARIABLES --------------------
unsigned long previousMillis = 0;
unsigned long lastPrintTime = 0;
unsigned long firstWallTime = 0;

bool lastWallState = false;
bool firstWallSeen = false;
bool measurementDone = false;

unsigned long segmentTime = 0;

// -------------------- RESET HELPER FUNCTION --------------------
// helper function to be used in main code to reset detectRotation variables
void resetDetectRotation() {
  previousMillis = 0;
  lastPrintTime = 0;
  firstWallTime = 0;

  lastWallState = false;
  firstWallSeen = false;
  measurementDone = false;

  segmentTime = 0;
}

// -------------------- DETECT ROTATION FUNCTION --------------------
unsigned long detectRotation() {
  unsigned long currentMillis = millis();

  // only sample every sampleInterval ms
  if (currentMillis - previousMillis < sampleInterval) {
    return 0;
  }

  previousMillis = currentMillis;

  int sensorValue = robot.readIR();

  if (currentMillis - lastPrintTime >= printInterval) {
    lastPrintTime = currentMillis;
    Serial.print("IR: ");
    Serial.println(sensorValue);
  }

  bool currentWallState = (sensorValue > sidePassingThreshold);

  // rising edge means wall just started
  if (currentWallState && !lastWallState) {

    // this wall is the first wall
    if (!firstWallSeen) {
      firstWallSeen = true;
      firstWallTime = currentMillis;
      Serial.println("=== FIRST WALL DETECTED ===");
    }

    // this wall is the second wall (also ensure that measuremnt is reasonable)
    else if (!measurementDone && (currentMillis - firstWallTime >= minWallGap)) {
      segmentTime = currentMillis - firstWallTime;
      measurementDone = true;

      Serial.println("=== SECOND WALL DETECTED ===");
      Serial.print("Segment time: ");
      Serial.println(segmentTime);
    }
    else {
      Serial.println("Ignored false wall detection"); // false wall detection because measured gap was 
    }
  }

  lastWallState = currentWallState;

  // return result
  if (measurementDone) {
    unsigned long result = segmentTime;
    segmentTime = 0; // reset immediately
    return result;
  }

  return 0;
}

Final project: thermal rod boundary-value problem

In this project, I analyzed a slender rod that forms a critical part of a thermal control assembly to calculate the temperature along the rod by solving the boundary value problem for the steady-state temperature distribution. To find the most efficient numerical method, the ODE was solved using coarse, medium, and high-resolution cases of 5 nodes, 100 nodes, and 500 nodes. After computing the solutions to the ODE, at each resolution, a quadratic curve was generated to fit each data set to enable root finding. Then, using the coefficients of the fitted quadratic curves, the roots of each resultion were computed with the quadratic formula. As shown, the medium and high-resolution cases were nearly identical, and so mny recommendation was to use the medium resolution model to reduce required computational workload.

Thermistor calibration curve fitting project

In this project, I analyzed a set of thermistor calibration data to compare three curve fittin approaches: (1) quadratic least squares regression, (2) Newton's divided difference interpolation, and (3) natural cubic spline. The quadratic least-squares regression provided the most pratical and stable approximation for resistance values.

Coolant flow rate for an 80 °C processor project

Here, I fit polynomials of degrees 1, 2 and 3, to experimental data for high-performance processors to develop a model for temeprature variation with coolant flow rate and determin the flow rate that kept the processor at a target temperature of 80 °C. The third degree polynomial regression model provided the best fit for the noisy data with an R² value of 0.99858 and an RMSE value of 0.09272 °C. Bisection and secant methods of root finding that I coded converged to the same root (1.6267 L/s) as MATLAB's roots() function, confirming the accuracy of the procedure.
